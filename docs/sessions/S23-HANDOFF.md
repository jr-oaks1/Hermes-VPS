## 7. H9 — cloud-firewall Cloudflare-CIDR narrowing, applied with a real mitigation

**The conflict, surfaced and addressed, not overridden blindly:** S28 §13.2
already considered this exact change (narrow the Hetzner Cloud provider
firewall's `80`/`443` from "Any" to Cloudflare's CIDR ranges, matching UFW)
and rejected it — reasoning: ~29 hand-maintained rules that Cloudflare
periodically revises, and a stale copy becomes a silent outage; UFW already
enforces it, so a second drifting copy is worse than one control point.

**What S23 actually did, not a repeat of the rejected idea:** rather than
apply a static hand-copied list (exactly what S28 rejected), built
`check_cloud_firewall_cidr_drift()` — a new Tier 3 guardrail check that
re-fetches Cloudflare's live list (`https://api.cloudflare.com/client/v4/ips`,
public, unauthenticated) every 5 minutes and diffs it against whatever the
cloud firewall currently allows on `80`/`443` (via the new Hetzner Cloud API
access, §5), emitting WARNING the moment they disagree. Read-only — never
modifies the firewall itself. Degrades to an INFO "skipped" row if the
credential isn't configured. +5 tests
(`tests/test_cloud_firewall_cidr_drift.py`).

**Then applied the actual change:**

   left unchanged (HTTP 201, `success`).
