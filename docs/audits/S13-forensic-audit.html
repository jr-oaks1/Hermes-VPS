P1 High — fixed first

Neither was an infrastructure fault. Both were defects in the host's own tooling that had been degrading it quietly for ~10 days.

P1-1Host health monitoring was crying wolf since ~2026-08-26

Fixed
What
hermes-vps-healthcheck-weekly and hermes-vps-audit-monthly sat in a permanent systemd failed state; systemctl is-system-running reported degraded.
Cause
hermes_vps_health_check.py emitted a false CRITICAL every run, forcing a non-zero exit. SYSTEMD_SERVICES still listed the decommissioned hermes_v2; and check_api_health treated the agent state disabled (an operator choice, e.g. fred_data) as a fault.
Impact
Two real Telegram CRITICAL alerts per cycle for ~10 days → alert fatigue; the genuinely green checks underneath were invisible.
Fix
SYSTEMD_SERVICES → ("hermes-ingestor", "nginx", "postgresql"); "disabled" added to the benign-agent-state set; the hermes_v2 git-sync and findings-export calls removed entirely.
Verified
Manual --mode deep and a real systemctl start both → all findings INFO, exit 0. Host now running, systemctl --failed empty. Weekly timer re-armed for Sun 04:00 UTC.

P1-2Deploy clones diverged, and the export loop made it worse each run

Fixed
What
/opt/hermes-vps and /opt/hermes_v2 were each ahead 6 / behind 7 with dirty trees.
Cause
_commit_and_push_export() auto-committed docs/findings_export/latest.json and pushed on every run; both pushes were rejected non-fast-forward, so each cycle stacked another unpushable commit. The S11 daily-digest fix was stranded as an uncommitted on-disk edit.
Fix
Both clones hard-reset to origin/main (guarded — only when every local-only commit is an export chore). export_hermes_vps_findings() now runs _sync_repo_to_origin() before writing, and _commit_and_push_export() rolls its own commit back if the push fails. The clone cannot diverge again.
Verified
Post-run git status clean, ahead/behind 0/0; findings export committed and pushed cleanly (26e1dc1, fdc25e2).
